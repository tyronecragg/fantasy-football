## A. Fix before the GW3 deadline

1. **GW3 player archive is a synthetic carry.** `inputs/historical_player_data.csv` GW3 rows: 3+ Saves
   identical to GW2 for 67/68 keepers, Yellow Card identical for 616/616, none of the saves match the
   live master. The `--gw 3` run happened before Betway priced GW3. It will be overwritten by the
   deadline `--gw 3` run, but `outputs/training/train_saves3.csv` (rebuilt 09-01) and this week's
   trailing-median factors already include it. Root cause: `run.guard_synthetic_archive` (run.py:34-56)
   checks `provenance.is_real` per file but never that the manifest `gw` equals the run's gameweek.
   *Fix:* gate on `manifest.gw == gameweek`; re-run `--gw 3` at the deadline; rebuild training data.

2. **Fixture archive mislabels GW2 as GW3.** `inputs/historical_fixture_odds.csv` has 20 rows at
   Gameweek 3 and none at 2; rows 231-240 (Crystal Palace v Man City, Aston Villa v Arsenal, ...) are

3. **Concede 4+ is silently zero for 18/20 teams.** Betway prices Team Over 3.5 for Liverpool and Man
   City only; `markets.py:110` does `fillna(0.0)`, so `F1 Concede 4+` = 0 → factor 0 → written into
   `fallback_factors.csv` (562/1053 rows now 0) and the trailing median for `concede4` locks at 0.
   Master: 99 of 109 starting GK/DEF have Concede 4+ = 0. Every defender is overstated by
   2 × P(4+) and teams facing City/Liverpool hit a cliff. *Fix:* keep NaN in improved mode and fall to
   fallback/median, or derive P(4+) from the over-1.5 line with the Poisson curve `score2` already uses;
   one-off repair of `fallback_factors.csv`; exclude zeros from `season_weekly_factors("concede4")`.

4. **Stale GW1 two-assists odds feed this week's F1 Assist 2+.** `sportsbet/sportsbet_two_assists_odds.csv`

7. **Unpriced starters get NaN factors → zero attacking XP for F2-F8.** `players.py:288,295`: when the

8. **`weekly_update.py` phase 2 bypasses the roll guard and uses the wrong python.** It runs a bare
   `build_fixtures.py --gw N` (line 118) instead of `roll_gameweek.py`, which README:35-37 and
   `roll_gameweek.py:6-9` forbid; and it launches `fpl_pipeline.run --gw` with `sys.executable`
   (lines 29, 130), which now hard-fails without lightgbm. Same interpreter issue in `roll_gameweek.py:32`.

8b. **Concede penalty is double the FPL rule (workbook-inherited).** `model.py:228` charges
    `2.0 × P(concede 2+) + 2.0 × P(concede 4+)` for GK/DEF; the workbook's AJ formula does the same.
    FPL deducts 1 point per 2 goals conceded, so the expected penalty is `1 × P(2+) + 1 × P(4+)`
    (+ P(6+)). Every GK/DEF is understated by roughly P(2+) + P(4+) ≈ 0.45–0.6 XP per fixture,
    biasing the optimiser toward attackers. Found 2026-09-01 while explaining the concede-4+ repair.
    **Fixed same day:** `model.xp_pre(concede_points=...)` charges 1 per threshold in improved mode
    (`CONCEDE_POINTS_FPL`); parity mode keeps the workbook's 2.0.
    Also added the same day (improved mode only): a third −1 at six conceded (`F{k} Concede 6+
    Goals`, Poisson tail off each fixture's 4+; ≈1% for most teams, 8% for Coventry at City) and a
    forward DC term (`F{k} Defensive Contribution - FWD`, threshold 12, `dc_params.csv` FWD row
    sd 2.45 / avg 0.03 from the DEF/MID method). Note the normal DC curve underestimates the forward
    tail (model ≈0.2% vs ≈3% empirical at mean dc90 — the known `dc_probability` TODO), so the
    term is structurally right but small; either way < 0.06 XP.
    Remaining scoring-rule gaps: appearance is a flat 2 × P(start), so <60-minute starters (1 pt),
    substitutes (1–2 pts) and the 60-minute clean-sheet condition are not modelled; own goals,
    penalty saves/misses and red cards are not modelled.
8c. **GW1 had no concede penalty at all.** The GW1 archive has `F1/F2 Concede 2+` NaN for every
    GK/DEF (team-goals market missing that week) on top of the 4+ zero, so GW1 defenders/keepers were
    overstated by ~1 XP each (starting GK/DEF mean F1 XP 4.02 vs MID/FWD 3.77; GW2: 2.98 vs 4.12).

## B. Models

9. **Refit holdout is not chronological.** `refit_coefficients.py:86-105` builds rows as
   `concat([home, away])` and cuts at 70%: train = 251 home + 100 away, holdout = 151 away rows whose
   matches all appear in train as the home mirror. 2025-26 fixture rows have Gameweek NaN, so no time
   order exists anyway. `projection_holdout_check` (:203-211) sorts Gameweek across seasons, putting
   2026-27 GW1-3 in train and 2025-26 GW25-29 in "holdout".
10. **Baseline OLS is unregularised on a rank-deficient design** (score1 rank 18/20, cond ≈ 5e15;
    `MIN_ROWS=100` for 20 params). Use ridge or drop the collinear `diff` terms.
11. **GBM training is pinned to `SEASON="2025-2026"`** (`train_projection_model.py:349`,
    `save_projection_models.py:523,561`, `walkforward_projection.py:78`), so "rerun after each new
    gameweek" adds nothing. The deployed models also never refit on the last 2 early-stop weeks.
12. **Win-probability scale mismatch.** 2025-26 archive F1 Win = 1/odds/1.03; 2026-27 uses the
    draw-aware 3-way split (`team_model.py:350-357`); the F3+ Lasso and `refit_coefficients.py:95` fit
    on the 1.03 scale. Factors are computed on one scale and applied on another (~1-1.5pp shift in
    every factor × baseline projection and in the GBM `form_win3/form_loss3` features).
13. **Clean-sheet de-margining is one-sided** (`markets.py:95-100`, 1/odds/1.05) although
    `clean_sheet_no` is in the file; measured overround is 1.075-1.083, so CS probs (GBM target,
    persistence feature, CS factor numerator) run ~2-3% hot. `concede_market` already does it two-sided.
14. **`fit_win_blend.midseason_frame` averages outrights over the whole season** (`fit_win_blend.py:410`),
    not point-in-time, so the 0.0478 blend CV in the README used future information.
15. **Trailing median double-counts the current week on re-runs.** `history.py:151` has no
    `Gameweek < gameweek` filter; after a `--gw N` run, later runs median over the archived GW N value
    and the recomputed one. When assist isn't real, the rebuilt factor × baseline value is archived as
    if it were an odds observation (`players.py:306-309`).
16. **Docs vs code on blending.** Assist is medianed always (`players.py:274-289`) while `run.py:117`,
    `config.py:94`, README:325 and the name `MEDIAN_FACTOR_STATS` say single-week. saves3 is served
    pure (`players.py:428,489`) while `config.py:83` and `players.py:479` say blended. README:299
    "probability space" vs code blending the rate.
17. **Feature distribution shift.** `top6` features are NaN in 18.4k/40k CS training rows (Top-6 odds
    only from GW21 2025-26) but always present in 2026-27 serving; serving passes NaN `persistence`
    where training dropped those rows. Form features key on `Player Name` not `player_id`
    (renames blank the window). Longshot calibration knots fitted on score1 are applied to assist and 2+.
18. **Hard-coded constants outside `coefficients.json`:** `model.py:248 BONUS_BY_RESULT`; GBM `DEPLOY`
    hyperparameters hand-copied from a walk-forward printout (`save_projection_models.py:534-540`);
    `fixture_weights` duplicated at `optimisation.py:217` and `:786`; `total_xp_weights` still in
    `coefficients.json`, `refit_coefficients.py:302`, `extract_coefficients.py:171`.
